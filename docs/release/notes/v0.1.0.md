# Leia v0.1.0

## Summary

- Version: v0.1.0
- Commit: the commit referenced by the Git tag `v0.1.0`
- Date: 2026-07-19
- Support targets: darwin and linux on amd64 and arm64, subject to the evidence below
- Packaging-only platforms: windows on amd64 and arm64
- Go version: 1.25.12
- Execution modes: interpreter and bytecode VM; Method JIT on supported ARM64 builds
- License: Apache-2.0

Leia v0.1.0 is the first public release of the Go-embeddable Leia scripting
language. It establishes the specification-covered language core, CLI,
bytecode VM, Go embedding API, module loading contract, standard-library
catalog, formatter, linter, test runner, LSP, and release tooling as the public
baseline for pre-1.0 compatibility.

## Compatibility

- Stable language changes: the language behavior documented by the generated
  specification and exercised by the release conformance gates forms the v0.1
  baseline.
- Experimental language changes: optional dialect extensions and newly added
  tagged forms may change with release notes before v1.0.
- Standard-library changes: documented default modules are part of the v0.1
  surface; provider-backed and capability-sensitive behavior remains dependent
  on host policy.
- Embedding API changes: the root `github.com/never-labs/leia` package is the
  supported Go embedding boundary. Packages under `internal/` are not public.
- CLI/tooling changes: `leia` and `leia-lsp` are the two distributed
  executables.
- Migration notes: this is the first public compatibility baseline.

## Highlights

- Go embedding through a small public VM, Program, Value, Module, Pool, and hot
  reload API.
- Interpreter and bytecode VM execution with ARM64 Method JIT acceleration
  where the release capability report enables it.
- Data-oriented arrays, structure-of-arrays frames, vectors, matrices,
  statistics, linear algebra, ODE, and control helpers.
- Extensible tagged dialects without expanding the stable core grammar for
  every domain.
- Formatter, linter, test runner, module tooling, LSP, playground, diagnostics,
  and machine-readable capability/release reports.

## Security

- `leia.New()` is a trusted-local runtime constructor and is not a sandbox by
  itself.
- Untrusted scripts must start with `leia.SecuritySandbox()`, explicit
  capabilities, bounded resources, and reviewed host bindings.
- Filesystem, environment, network, process, dynamic-evaluation, debug, and
  provider access depend on host configuration.
- Provider secrets belong in host configuration or environment variables, not
  Leia source files.
- Security reports use GitHub private security advisories, with
  `security@never-labs.com` as the fallback contact.

## Performance

Performance evidence is workload- and platform-specific. The release workflow
must pass the repository performance gate with its command, hardware, Go
version, LuaJIT availability, result artifact, and caveats recorded. v0.1.0
does not promise that every program or execution mode outperforms another
language runtime.

```bash
scripts/run.sh perf --full
```

## Validation

The tagged release is publishable only if these commands pass on the release
commit. Hosted CI provides linux/amd64 evidence; darwin/arm64 evidence is
recorded from the release worktree. Cross-compiled archives alone do not count
as runtime evidence for other combinations.

```bash
go run ./cmd/leia ci release --release-version v0.1.0
scripts/run.sh production --full --release-profile --release-version v0.1.0
scripts/run.sh test release-matrix
scripts/run.sh docs
scripts/run.sh perf --full
scripts/run.sh public-blockers --require-resolved
scripts/run.sh release-dist --require-goreleaser
scripts/run.sh release-notes --require-ready --version v0.1.0
scripts/run.sh release-check --build --require-clean --require-tag --version v0.1.0
go test -tags leia_q ./...
```

## Known Issues

- Windows archives are packaging targets without a v0.1 runtime support claim.
- Method JIT is an ARM64 optimization and is not a whole-language native-code
  compatibility contract; unsupported paths fall back to the VM.
- The in-repository q provider is an experimental extension enabled with the
  `leia_q` build tag. It is outside the default product and compatibility
  surface.
- Live AI providers and external services are not exercised by offline release
  validation.

## Release Decisions

- License: Apache-2.0.
- Security reporting: GitHub private security advisories with the documented
  fallback email.
- Platform support: darwin/linux on amd64/arm64 when backed by release evidence;
  Windows remains packaging-only for v0.1.0.
- Release channels: GitHub Releases, the checksummed installer, and explicit Go
  install commands for `cmd/leia` and `cmd/leia-lsp`.
- Artifact signing: SHA256 checksums are required; signature and provenance
  attestations are deferred beyond the first public release.
- Compatibility policy: specification-covered core behavior is maintained
  where practical before v1.0; experimental surfaces may change with release
  notes and migration guidance.
